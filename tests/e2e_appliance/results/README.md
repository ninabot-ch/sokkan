**The T10 check changed after `ea3603c`** (`suite.py`, bench only). It asserted that
`scripts/verify-release.sh` was gone after the rollback — a file 3.6.0 carries too, so the check
could not hold from 3.6.0. It now compares the two tarballs: no file that only the newer release
has may remain inside a release folder (300 files from 3.4.6, 271 from 3.5.1, 2 from 3.6.0), and
what remains at the top level is recorded (`left_at_top_level`). `3.6.1_ea3603c.json` was played
with the old check, the three `from-` files with the new one. **What it measured**: after a
rollback from 3.6.1 to 3.4.6 or 3.5.1, `docker-compose.doc-ingest.yml` (a top-level file new in
3.6) stays in the tree — `rollback.sh` removes the release folders and the entries of the target
release only. Nothing remains after a rollback to 3.6.0. A first play from 3.5.1 with a check
that refused any leftover failed T10 on that file alone (T9 not played); it is not kept.
